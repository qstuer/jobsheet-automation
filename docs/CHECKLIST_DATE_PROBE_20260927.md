# PM 檢查表跨頁日期，只讀全樣本試驗（2026-09-27）

目的：調查完整單據 B01、B04、B06、B07、B10 因首頁日期辨識不穩而停下，能否安全使用後續 PM 檢查表日期。模型只看單一固定日期欄；人工答案只在讀完後匿名評分，沒有提供 Asana 候選或答案。沒有上傳、移動或改名任何正式檔案。

試驗在獨立分支進行：[第一次](https://github.com/qstuer/jobsheet-automation/actions/runs/36298225495)、[分開評分的第二次](https://github.com/qstuer/jobsheet-automation/actions/runs/36298522877)。第二次有 16 張已核實的完整 PM、3 張缺頁跳過、1 張答案未核實跳過；64 次模型調用，DeepSeek 費用保守上限約 ¥0.053。

| 第二次讀取結果 | 正確份數／16 |
| --- | ---: |
| 第一張 PM 檢查表日期，兩次一致且等於核實日期 | 10 |
| 最後一張 PM 檢查表客戶簽署日期，兩次一致且正確 | 7 |
| 兩處均兩次一致、彼此一致，且正確 | 4 |

這五張停下的完整單據（B01、B04、B06、B07、B10）在第二次試驗中，第一張檢查表的日期均讀對。然而，B08、B09、B19 的檢查表首頁日期沒有正確核實；B19 的兩處甚至一致地讀錯。第一次只有 3 張兩處一致且正確，第二次為 4 張，亦顯示圖片模型讀數不穩定。**不能把「兩次讀一樣」或「兩頁讀一樣」直接當成日期真實性的證明。**末頁印章覆蓋簽署資料，不能成為每張單的必要條件。

目前不改正式配對。候選的下一條通用規則須同時滿足：

1. 只在既有流程已停下時作後備，絕不覆蓋已可靠選對的工作。
2. 第一張檢查表日期雙讀一致，並獲首頁 ACTION DATE 或首頁客戶簽署日期的獨立同值支持；有明確衝突便停下。Asana 日期只用於之後核對，不能替 OCR 填答案。
3. 設備身分、PM／CM、Asana 正式到期／完成日期及同設備其他歷史工作仍獨立檢查；不能只因日期接近就接受一字錯誤的機身編號。
4. 在同一 20 張和之後未用來設計規則的新單據上驗證，要求錯誤自動匹配為零；缺頁及答案未核實者分開計數。通過前維持只讀，不接 OneDrive。

## 受控後備規則回測

獨立測試分支新增一條只讀規則：只在原配對已停下、PM PDF 恰好四頁時，讀第一張 PM 檢查表頂端的日期兩次。兩次必須一致、在有效日期範圍內，且首頁 ACTION DATE 至少有一次同值；此外，首頁客戶簽署日期也須同值，或首頁 ACTION DATE 的兩次單格讀取都同值。若客戶簽署日期與之相反，或首頁 ACTION DATE 兩次一致地指向另一日期，立即否決。日期通過後仍須重新經過原有的設備與 Asana 工作唯一性檢查。這不是在模型提示中加入 Asana 答案，也不會因後頁重複讀取就直接選工作。

本機合成測試包括「後頁兩次一致但錯誤」、首頁衝突、缺少獨立支持和模型不可見 Asana 候選；全套 350 個測試通過。[20 份私人只讀回測](https://github.com/qstuer/jobsheet-automation/actions/runs/36299133458)結果如下：已核實且完整的 16 份中，12 份正確選定設備、工作和檔名（前次 11 份）；B01 新增通過，B04、B06、B07、B10 仍停下。原本通過的 11 份沒有退步；沒有觀察到錯誤自動匹配。B16、B17 缺頁，B18 只作缺頁診斷，B05 的人工答案未核實，均不算完整成功。346 次圖片調用，DeepSeek 費用保守上限約 ¥0.70。

匿名診斷顯示：B04 缺首頁獨立日期支持；B06、B07、B10 的首頁資訊與檢查表日期存在衝突。不能為了讓它們通過而忽略首頁證據。這條規則只能安全救回一部分樣本，**尚未達到全部完整樣本通過的驗收標準**。目前只在獨立分支；沒有更改正式 Stage B、OneDrive 或 Google Drive 工作單。下一步應分開調查這四份的首頁小格是否裁切／辨認不佳，以及同設備多次工作的任務識別，不應再單純放寬日期門檻。

## 首頁客戶日期分段讀取對照

親自檢查 B04、B06、B07、B10 原件與模型實際收到的裁切卡：首頁 ACTION DATE 和 PM 檢查表的筆畫仍在圖內；B04 客戶簽署日有印章壓在部分筆畫上。裁切並非四張共同的缺字原因。相同模型對清楚但潦草的手寫數字仍會輸出不同月份、年份或無法讀取。

[8 份只讀對照](https://github.com/qstuer/jobsheet-automation/actions/runs/36305009398)比較「一次讀完整日期」和「分別讀日／月／年」，包含四張難例及先前通過／曾穩定讀錯的對照樣本。分段讀法沒有穩定救回 B04、B06、B07、B10；B06、B10 各僅其中一輪讀對，B07 兩輪仍錯，且 B19 由原本兩輪正確變成不一致。**不把分段讀法接入正式或測試配對。**實驗只輸出匿名對錯狀態，沒有 Asana 查找、OneDrive 寫入或來源搬移。
